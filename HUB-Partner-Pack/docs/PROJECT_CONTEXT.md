## Vision

HUB is a unified multi-service application where users can access several daily-life digital services from one platform instead of installing and managing multiple separate applications.

The platform is inspired by the integrated-service concept used by super-apps such as Grab, but HUB is not intended to reproduce every commercial feature of those platforms.

The FYP should demonstrate a technically strong, integrated, realistic prototype.

---

## Core Problem

Users currently rely on multiple independent applications for:
- rides,
- food,
- shopping,
- fitness,
- bills,
- education payments,
- transaction records,
- expense tracking,
- and service discovery.

This causes fragmentation of user data, transaction history, service access, and recommendations.

Service providers also use disconnected workflows for managing customers, orders, bookings, payments, and records.

---

## Proposed Solution

HUB combines multiple services inside one role-based platform, accessed through a React website and a React Native Android/iOS application using the same backend APIs.

A customer can use multiple services from one account, while riders, restaurants, merchants, fitness providers, institutions, billers, and administrators receive interfaces and permissions appropriate to their roles.

The platform will also maintain unified activity, transaction, and expense data that can support personalized recommendations.

---

## Key Objectives

1. Build one integrated application for multiple service categories.
2. Implement secure authentication and role-based authorization.
3. Provide ride-hailing functionality through HUB Drive.
4. Support food ordering and dining-related services.
5. Support grocery and e-commerce marketplace features.
6. Support fitness and wellness discovery/bookings.
7. Support utility and education payment workflows.
8. Maintain unified transaction and expense history.
9. Provide reviews and ratings.
10. Implement notifications.
11. Develop a recommendation component using user and service data.
12. Integrate maps, OCR, notifications, payment, and bill APIs where appropriate.
13. Keep the prototype realistic for an academic FYP.

---

## Scope Philosophy

The platform should prioritize integration quality over feature count.

Not every commercial feature of:
- Grab,
- Foodpanda,
- Uber,
- ClassPass,
- Daraz,
- Easypaisa,
- JazzCash,
or similar platforms needs to be recreated.

The final defense should demonstrate strong technical modules working together.

---

## Major Technical Contribution

A major technical focus is the recommendation system.

The platform can use:
- user history,
- orders,
- bookings,
- ratings,
- searches,
- location,
- popularity,
- time,
- price range,
- and similar-user behavior

to recommend restaurants, products, activities, providers, offers, or frequently used services.

Rule-based recommendations may be used initially, while an ML-based approach should be developed where practical.
